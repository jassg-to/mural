### Layer: DRM Backend

- [x] Step 4: Create `drm_ioctl.go` — raw ioctl request constants and C-struct-layout Go structs for `SET_MASTER`/`DROP_MASTER`, `GET_RESOURCES`, `GET_CONNECTOR`, `GET_ENCODER`, `CREATE_DUMB`, `MAP_DUMB`, `ADD_FB`, `SET_CRTC`, `PAGE_FLIP`. (Also includes `DESTROY_DUMB` — omitted from this step's original list but required by Step 10's `Close()`, and the same category of raw constant as the rest of this file; adding it here avoids a second, later edit to this file.)
- [x] Step 5: In `drm_ioctl.go`, add pure helper `pickPreferredMode(modes []drmModeInfo) drmModeInfo` (index-0 selection, matching the board's own `modetest -c` ordering).
- [x] Step 6: In `drm_ioctl.go`, add pure helper `rgbaToXRGB8888(dst []byte, pitch int, src *image.RGBA)`.
- [x] Step 7: Add `TestPickPreferredMode` and `TestRGBAToXRGB8888` in `slideshow_test.go` — no hardware required.
- [x] Step 8: Create `drm.go` — `DRMRenderer` struct and `OpenDRMRenderer(devicePath string) (*DRMRenderer, width, height int, err error)`: acquire master, enumerate the connected connector, pick its mode via `pickPreferredMode`, allocate and map two dumb buffers. Each acquisition (fd open, `SET_MASTER`, buffer 1 create/map, buffer 2 create/map) gets its cleanup deferred immediately after it succeeds — not batched at the end — so a failure partway through (e.g. buffer 2's map fails after buffer 1 already succeeded) unwinds everything acquired so far via a named-error return path, per `CLAUDE.md`'s "use `defer` for cleanup immediately after acquiring the resource." A partial failure that leaks DRM master is exactly the failure mode this design exists to avoid.
- [x] Step 9: In `drm.go`, implement `(*DRMRenderer) Present(frame *image.RGBA) error` — `nil` frame composites black via `compositeLetterboxed`, converts via `rgbaToXRGB8888` into the back buffer, page-flips, waits for the flip event, swaps front/back. A page-flip failure because no display is attached (HDMI unplugged) is returned as an ordinary error like any other page-flip failure — no special detection, no panic, no retry loop inside `Present` itself; the caller (run loop) logs it and moves on, and a later reconnect is picked up reactively the next time `Present` is called for a slide change.
- [x] Step 10: In `drm.go`, implement `(*DRMRenderer) Close() error` — unmap and destroy both dumb buffers, drop master.
- [x] Step 11: Create `vt.go` — install `SIGUSR1`/`SIGUSR2` handlers (`VT_SETMODE(VT_PROCESS)` on the controlling tty) that drop/reacquire `DRMRenderer`'s master and re-set the mode on VT switch-away/back.
- [x] Step 12: In `vt.go`, install `SIGTERM`/`SIGINT` handling that calls `DRMRenderer.Close()` and restores the console to text mode (`KDSETMODE(KD_TEXT)`) before exit. (Reconciled with Architect.md's Approach section and Step 21, which are more specific about sequencing: `vt.go`'s handler calls `cancel()` — the same shutdown mechanism `NavQuit` uses — and exposes `RestoreConsole()`; `main.go` calls `renderer.Close()` then `vt.RestoreConsole()` after `Run()` actually returns, so console restore never races the still-active DRM calls a mid-shutdown run loop could still be making.)

### Layer: Input

- [x] Step 14: Create `input.go` — `NavKey` type (`NavLeft`, `NavRight`, `NavHome`, `NavSleep`, `NavQuit`, `NavWake`) and a pure `parseInputEvent(raw []byte) (key NavKey, ok bool)` decoding a raw `input_event` struct: `KEY_LEFT`/`KEY_RIGHT`/`KEY_HOME`/`KEY_DELETE`/`KEY_ESC` map to their named `NavKey` on either `value == 1` (initial press) or `value == 2` (kernel autorepeat) — both are key-down states and must be treated identically; any other key on `value == 1`/`value == 2` maps to `NavWake`; `value == 0` (key-up) and non-`EV_KEY` events return `ok == false`.
- [x] Step 15: Add `TestParseInputEvent` in `slideshow_test.go` covering each of the five named keys at `value == 1`, the same five at `value == 2` (autorepeat — asserting identical `NavKey` output to `value == 1`), an arbitrary other key-down (→ `NavWake`), and a key-up (→ `ok == false`) — no hardware required.
- [x] Step 16: In `input.go`, add device enumeration and hotplug: open all readable `/dev/input/event*` nodes, watch `/dev/input` via `inotify` for new nodes, forward parsed `NavKey`s from every open device into one `Events() <-chan NavKey`, and drop a device's watcher quietly on read error (unplug) without affecting the others. Accept a `context.Context` so every enumeration/watcher goroutine exits on `ctx.Done()` instead of leaking past `Run()` returning (per `CLAUDE.md`'s context-for-cancellation convention).
