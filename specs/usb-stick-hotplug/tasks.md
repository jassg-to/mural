### Layer: Media Detection

- [x] Step 3: Create `media.go` with pure `parseMountinfo(r io.Reader) ([]string, error)` returning every mount point in `/proc/self/mountinfo` format. The mount point is **field index 4 (0-based)** on each line and its position is fixed — the variable-length optional-field run and the `-` separator sit *after* it, so locating `-` is only necessary if the parser ever returns fields beyond the mount point (it does not; do not over-engineer this). The trap that does matter is escaping: octal sequences in the mount-point field (`\040` space, `\011` tab, `\012` newline, `\134` backslash) must be decoded, or a stick labelled `MY STICK` is silently lost. Lines with fewer than 5 fields are skipped, not errors — `/proc` can be read mid-write.
- [x] Step 4: In `media.go`, add pure `newMountPoints(prev, cur map[string]bool) []string` returning the entries present in `cur` and absent from `prev`, sorted for determinism. Also add pure `underRoot(mountPoint, root string) bool`: true only when `mountPoint` is strictly below `root`, compared **separator-aware** — `strings.HasPrefix(mp, root+string(os.PathSeparator))` after `filepath.Clean` on both, never a raw prefix test, or `/media/mural-backup/x` would be treated as a volume under `/media/mural`. Keeping this pure is what makes that case unit-testable; the watcher must call it rather than inlining a prefix check.
- [x] Step 5: Create `media_test.go` with `TestParseMountinfo` (a realistic multi-line sample including a mount point with an escaped space, a line with zero optional fields, a line with several, and a truncated line that must be skipped rather than erroring), `TestNewMountPoints` (first-observation case where `prev` is empty, no-change case, addition, removal-then-re-addition), and `TestUnderRoot` (direct child true; `root` itself false; the `/media/mural-backup` sibling-prefix case false; trailing-slash forms of `root` handled identically).
- [x] Step 6: In `media.go`, add `MediaWatcher` with `NewMediaWatcher(ctx context.Context, root string) (*MediaWatcher, error)` and `Events() <-chan string`. Open `/proc/self/mountinfo` and run a goroutine that blocks in `unix.Poll` on `POLLPRI|POLLERR`; on each wake re-read from offset 0 (`Seek(0, io.SeekStart)` then read to EOF — a seq_file regenerates its contents from the seek), parse, filter with `underRoot`, diff against the tracked set via `newMountPoints`, and send each new mount point on the channel — **guarding every send with `select { case ch <- mp: case <-ctx.Done(): return }`**, exactly as `input.go:172-176` does. An unguarded send blocks forever if `Run` is not reading (shutdown, or a run loop busy elsewhere), and a goroutine parked on that send never reaches its `ctx` check and never closes the file. Drop disappeared mount points from the tracked set so a re-inserted stick is seen again.

  **Poll for `unix.POLLPRI` only.** Do not add `POLLIN`: `mounts_poll` in the kernel returns `EPOLLIN|EPOLLRDNORM` *unconditionally* on every call, so requesting `POLLIN` makes `Poll` return instantly forever — a 100%-CPU busy loop on a passively-cooled Pi. `POLLERR` needs no requesting (it is always reported), so `POLLPRI` alone is both necessary and sufficient. This is the natural thing to get wrong, because `POLLIN` is what one reaches for when polling a file.

  **Three further loop details are load-bearing and none of them are optional:**
  - **`unix.Poll` must be called with a finite timeout (1000 ms), not `-1`.** A `-1` poll blocks forever and `ctx.Done()` cannot interrupt it; closing the fd from another goroutine does *not* reliably wake a thread blocked in `poll(2)`. The loop checks `ctx.Err()` on every timeout and returns, closing the file. This is the cancellation path — `input.go`'s close-the-fd shape works for `read(2)` on a device and must **not** be copied here.
  - **`unix.EINTR` must be retried, not treated as an error.** The Go runtime delivers `SIGURG` for async preemption, which interrupts blocking syscalls routinely; returning on `EINTR` would kill the watcher within minutes of normal operation and the feature would fail silently on the board while passing every unit test.
  - **A `POLLPRI` wake is not required to make progress.** Re-read and diff on the poll timeout as well, at a coarse interval (every 5th timeout ≈ 5 s), so that if `POLLPRI` never fires on the target kernel the feature degrades to 5-second detection latency instead of being completely inert. Architect.md names a silently non-firing watcher as the single highest risk in this design and this is the only in-code defence against it; the cost is parsing ~40 lines of `/proc` every 5 s.

  An empty `root` disables the watcher outright (inert, channel never fires). A `root` that **does not exist is logged as a warning but the watcher still runs** — mount points under a nonexistent root simply never appear in `mountinfo`, so there is nothing to guard against, and an install that creates `/media/mural` after Mural started would otherwise stay broken until a restart. Neither case is a startup failure.

### Layer: Ingest Transaction

- [x] Step 7: Create `ingest.go` with `type volumeDisposition int` (`volumeIgnored`, `volumeRejected`, `volumeAccepted`) plus a `String()` for logging, and `classifyVolume(mountPoint string) (volumeDisposition, *Config, error)`. The stat of `<mountPoint>/config.toml` has **three** outcomes, not two, and conflating them is what makes an unreadable stick undiagnosable:
  - `errors.Is(err, fs.ErrNotExist)` → `volumeIgnored`, nil config, **nil error**. This is the expected outcome for a personal flash drive and must not be logged as a failure.
  - **any other stat error** (`EACCES` on the volume root, `EIO` from a corrupt filesystem, the mount vanishing mid-classify) → `volumeRejected` with that error wrapped. The Analyst's "volume mounts but is unreadable → ingest failure, logged" case lands here; treating every stat error as "absent" would silently swallow it into *ignored*.
  - stat succeeds but the entry is not a regular file (a directory named `config.toml`) → `volumeRejected` with a descriptive error. Choose *rejected* deliberately: the name is present, so the volume is addressed to Mural and is broken.

  Then `LoadConfig` fails → `volumeRejected` with the parse error; `hasAnyOnWindow(cfg.Schedule)` false → `volumeRejected` with a descriptive error naming the "no on-window" reason; otherwise `volumeAccepted` with the parsed config. The name is matched case-sensitively as exactly `config.toml`. On the *ignored* path only, additionally scan the volume's top level for a case-insensitive match (`Config.toml`, `CONFIG.TOML`) and, if one exists, log at info level that a differently-cased config was found and ignored. *Ignored* is the silent disposition and therefore the hardest to diagnose; this one log line turns "a Windows-prepared stick does nothing" from a mystery into a readable answer, and costs one `ReadDir` on a path that is already returning.
- [x] Step 8: Create `ingest_test.go` with `TestClassifyVolume` using `t.TempDir()`: no config (ignored, nil error); unparseable TOML (rejected); valid TOML with no on-window (rejected); valid TOML with an on-window (accepted); a **directory** named `config.toml` (rejected, per Step 7's deliberate choice); a volume root whose permissions make the stat fail (rejected, **not** ignored — skip this subtest when running as root, where the mode is not enforced); and a `Config.toml` with no `config.toml` (ignored, with the diagnostic log path exercised).
- [x] Step 9: In `ingest.go`, add **`imageFilesIn(dir string) ([]volumeFile, int64, error)`** where `volumeFile` is a small local struct (`name string; size int64`) — not `os.FileInfo`, which is the legacy interface and carries no useful extra information here. This one function is used for **both** the volume and the content directory; `volumeImages(mountPoint)` is just a call to it. That is deliberate, because Steps 12 and 13 also need to enumerate "the active images in `content/`" and "the image files in `previous/`", and if those grow their own ad-hoc predicates the results diverge.

  **The predicate must be exactly `isImageExt(filepath.Ext(name))` plus `fi.Mode().IsRegular()` — the same test `scanSlides` applies (slideshow.go:95-102).** Getting this wrong is not cosmetic: the obvious naive implementation for Step 12b, "rename every non-directory entry out of `content/`", would sweep `content/config.toml` into `previous/`, and Step 12c's `os.Link(content/config.toml, ...)` would then fail with `ENOENT` *after* 6b had already moved the images — converting the happy path into a `mutated` failure on every single accepted ingest. The rotation and the ingest must agree on what an image is, and the only way to guarantee that is one shared function.

  Enumerate the directory's **top level only** (no recursion, matching the content directory's existing flat treatment) via `os.ReadDir`, and for each entry take `d.Info()` — **not `os.Stat`**: `d.Info()` has `lstat` semantics and does not follow symlinks, so a symlink named `big.jpg` pointing at `/dev/zero` or at a file outside the volume is skipped rather than copied. Keep an entry only when `fi.Mode().IsRegular()` (a FIFO or device node named `x.jpg` would otherwise hang `io.Copy` forever on the background goroutine, with the sign still running and no indication why the ingest never completes) and `isImageExt(filepath.Ext(name))` passes. Return the entries and their total byte size. Use `filepath.Base(name)` when constructing destination paths — `ReadDir` names cannot contain a separator, so this is defence in depth, not a live traversal fix.
- [x] Step 10: In `ingest.go`, add `availableBytes(dir string) (uint64, error)` using `unix.Statfs`, returning `uint64(st.Bavail) * uint64(st.Bsize)` — **both conversions are required**: `Bsize` is `int32` on `GOARCH=arm` and `int64` on arm64/amd64, and armv7 is a published release target, so an unconverted multiply is a compile error on one of the three CI architectures. Define `ingestFreeSpaceMargin = 32 << 20`. The free-space check is `needed + margin <= available`; `ingestVolume` takes the availability function as a parameter so tests can inject a constrained value without needing a small filesystem.
- [x] Step 11: In `ingest.go`, add the staging half: create `content/.ingest-staging/` (removing any stale one first), copy each volume image and the volume's `config.toml` into it opening every source **read-only and never writing to the volume**, `fsync` each destination file, verify each copy's written byte count equals the source's stat size, then `fsync` the staging directory. Any error — including `ctx.Done()` between files, so a shutdown mid-copy does not leave scratch behind — removes the staging directory and returns the failure.
- [x] Step 12: In `ingest.go`, add the commit half, the only window that mutates the active content directory. **The retention slot is reclaimed per-payload, not wholesale** — see Architect.md, "Retention is reclaimed per payload":
  a. `os.MkdirAll` `content/previous/` (do **not** blanket-delete it; Step 13's reclaim has already emptied it of images if that was warranted).
  b. **Only when the volume supplied at least one image:** `os.Rename` every active top-level image out of `content/` into `previous/` — the set being **exactly `imageFilesIn(contentDir)` from Step 9**, never an ad-hoc "every non-directory entry", which would sweep `config.toml` along with them and break (c) — then `os.Rename` every staged image from `.ingest-staging/` into `content/`.

     **If any rename in (b) fails, roll back before returning.** The images already moved into `previous/` are on the same filesystem and are renameable straight back into `content/`, which restores the Analyst's "leave the running player in the state it was in before the volume was seen" exactly, rather than settling for the `mutated` repair path. Attempt the rollback, and only if the rollback *itself* fails set `mutated` and report. This matters most in the worst case the un-rolled-back design allows: a failure after every active image has moved out but before any staged image has landed leaves `content/` with no images at all, which Step 20 then faithfully adopts as the waiting state — a stick that fails mid-commit would black the sign completely. Rolling back turns that into a no-op.
  c. **Always**, and atomically: `os.Link(content/config.toml, previous/config.toml)` — after removing any existing `previous/config.toml` — and then `os.Rename(.ingest-staging/config.toml, content/config.toml)`. Link-then-rename rather than rename-then-rename because the latter leaves a window in which `content/config.toml` **does not exist**, and `Schedule`'s daily `reload()` reads exactly that path from another goroutine. `os.Rename` over an existing destination is atomic on Linux, so no reader ever sees a missing or half-written config. If `os.Link` fails (it cannot on a single ext4 filesystem, but fail closed), fall back to copying the old config into `previous/` before the rename.
  d. Remove the emptied `.ingest-staging/`.

  Step (b) being conditional is the entire config-only case — an accepted volume with no images must leave the rotation exactly as it was and must never empty it. Leaving `previous/`'s *images* untouched in that case is the fix for the same rule's mirror image: a settings-only stick must not destroy the operator's recovery copy of a content set it never displaced.

  **Every error return from (b) onward must report that the content directory was mutated** (see Step 13's `mutated` flag). Once the first rename in (b) has succeeded, the "leave the player exactly as it was" guarantee no longer holds and the caller has to be told.

### Layer: Schedule Live Application

- [x] Step 23: In `schedule.go`, add a `replan chan struct{}` field (buffered, capacity 1) and `ApplyConfig(cfg ScheduleConfig)` which swaps `s.cfg` under the existing mutex and signals `replan`. **The signal must be a non-blocking send** — `select { case s.replan <- struct{}{}: default: }` — not a plain `s.replan <- struct{}{}`. A capacity-1 channel with a pending unconsumed signal blocks a plain send, and `ApplyConfig` is called from the ingest-result handler on the **run-loop goroutine**, so a blocking send there freezes the sign. "Buffered so repeated signals coalesce and never block" is only true of the `select`/`default` form; the buffer alone does not give you either property. Initialise `replan` in `NewSchedule` — a nil channel would make the `select` in `Start` block forever on that arm and silently never re-plan.

  Rewrite `Start`'s event goroutine so **both** of its sleeps become `select`s over `time.After(...)` and `<-s.replan`. There are two, and missing the second one defeats the entire purpose of this step:
  - the per-event sleep, `time.Sleep(time.Until(e.at))` at **schedule.go:237**, inside the `for _, e := range future` loop; and
  - the until-midnight sleep, `time.Sleep(time.Until(tomorrow))` at **schedule.go:245**, which sits *outside* that loop.

  "Break out of the event loop" only covers the first. But consider the headline scenario this whole step exists for — a stick inserted during scheduled off-hours. Off-hours is exactly when the day's remaining events have already fired, so `future` is empty, the `range` completes immediately, and the goroutine is parked on line 245 waiting for midnight. A re-plan that only breaks the inner loop never reaches it, and the adopted schedule takes effect at 00:00 rather than now. The fix is that the re-plan arm on **either** select `continue`s the outer `for` loop and recomputes from scratch. Stop each `time.After` timer on the re-plan path rather than leaking one per signal.

  The existing loop already drops events whose time has passed (schedule.go:226-231), which is what prevents a double-fire after a re-plan — keep that filter and apply it to the recomputed list too. **Extract that filter as a pure function** (`futureEvents(events []event, now time.Time) []event`) so Step 24 can assert the no-double-fire property directly instead of racing a wall clock. Have `reload()` signal `replan` too, so the daily config re-read inherits the same immediate effect. The `reload_time` goroutine needs no change — it recomputes its own next wake from `s.cfg` every iteration.

  **Document the known consequence rather than engineering around it:** recomputation drops events already in the past, so a config adopted at 14:00 whose on-window is 08:00–20:00 produces only an *off* event today. The display is nonetheless on, because the ingest woke it directly — the wake and the schedule are independent, and this is exactly the pre-existing nav-key wake semantics the Analyst chose to inherit. Do not add a synthetic catch-up "on" event; that would be new behaviour the Analyst did not ask for.
- [x] Step 24: In `slideshow_test.go`, add `TestScheduleApplyConfig`: `IsOn` reflects the new config immediately after `ApplyConfig`; and a repeated `ApplyConfig` does not block (call it several times in a row with nothing draining `replan` and assert the calls return — this is the direct regression test for the non-blocking send).

  For the no-double-fire property, assert against the **pure `futureEvents` filter** extracted in Step 23 — feed it a hand-built event list and a fixed `now`, and assert past events are dropped and future ones kept. Do **not** write this as "call `ApplyConfig`, sleep, and observe whether a callback fired": `Schedule` has no injectable clock, so that form is a wall-clock race that will flake in CI and teach whoever hits it to add a longer sleep. ### Layer: Slideshow Ingest Wiring

- [x] Step 25: In `slideshow.go`, add a `mediaCh <-chan string` parameter to `Run` and a `case mp := <-s.mediaCh:` to the run loop. It must **not** perform the ingest: if no ingest is in flight, set an `ingesting` flag and launch a goroutine calling `s.ingestFn(s.ctx, mp, s.dir, availableBytes, onCommit)` — where `onCommit` posts `ingestCommitMsg{}` into `cmdCh`, see (c) — that then posts an `ingestResultMsg` back into `cmdCh`; otherwise append the mount point to a pending queue. This is the one-at-a-time serialisation and the "display keeps playing during the copy" requirement, both satisfied by never doing filesystem work on the run-loop goroutine.

  Four details:

  (a) **The body of that case must be an extracted method, `handleMediaMount(mp string)`, not inline code in the `select`.** The run loop's case is then one line calling it. Without this Step 27 is unwritable: `mediaCh` is read only inside `Run`'s `select`, and `newHeadlessSlideshow`'s own doc comment (slideshow_test.go:348-353) says `Run` cannot be called from a test — so "two mount points are processed strictly one at a time" and "the same mount point arriving twice is enqueued once" have no way to drive the queue at all. Extracting the method gives the tests a seam and costs nothing. Do the same for the `ingestResultMsg` handling in Step 26 if it does not already fall out of `handleCommand`'s existing shape.

  (b) Add an `ingestFn` field of the same signature as `ingestVolume`, defaulted to `ingestVolume` in `NewSlideshow`, so Step 27 can substitute a fake without a real filesystem — Step 27 asks for a fake ingest hook and a hardcoded call makes that impossible.

  (c) **Add an `ingestCommitMsg{}` barrier so the commit cannot blank the sign.** The Analyst forbids the display blanking, stalling, or showing partial results mid-ingest, and the design as written violates that in a narrow but real window: the commit renames active image files on the background goroutine while the run loop's `advanceTimer` is still armed against `s.slides`, whose paths now point into `previous/`. An `advanceMsg` landing in that window calls `show`, the decode fails on a missing file, and `compositeLetterboxed(nil, ...)` presents a **solid black frame** — precisely the partial result the Analyst rules out. So: the ingest goroutine posts `ingestCommitMsg{}` immediately before it begins the commit, and the run loop's handler stops `advanceTimer` and sets an `ingestCommitting` flag that makes `advanceMsg` a no-op. The flag is cleared by the `ingestResultMsg` handler, whose rescan (on success) or repair (on `mutated`) re-arms the timer; clear it on *every* result path, including ignore and reject, so a bug cannot strand the rotation frozen. Nothing is presented in between, so the display simply keeps scanning out the frame it already had — which is exactly "continue displaying the currently playing content until the ingest is complete".

  (d) The pending queue must **skip a mount point already queued or in flight** and cap at a small bound (8), **logging at warning level when the cap forces a drop**. A stick reconnecting repeatedly — a flaky USB port, a marginal cable, a hub that re-enumerates — would otherwise grow the queue without limit and re-run identical ingests for minutes after the operator walked away. Dropping duplicates is safe precisely because the Analyst defines re-ingest as idempotent in result; dropping *past the cap* is a real loss of an event, so it must not be silent — an operator whose stick was ignored because a queue overflowed needs that in the log.
- [x] Step 26: In `slideshow.go`, handle `ingestResultMsg`: clear the `ingesting` flag and start the next queued mount point if any, then dispatch on disposition:
  - **accepted** — log at info level (mount point, image count, whether images were applied); call `s.applySlideshowConfig(cfg.Slideshow)` — **the direct, non-posting form from Step 21; calling the exported `ApplyConfig` here deadlocks the run loop** — then invoke the injected schedule-apply callback with `cfg.Schedule` (nil-check it: `main.go` wires it after construction, and the tests may not wire it at all), then `startRescan(true, true)`, the second `true` forcing every thumbnail to be re-decoded at the possibly-changed `thumb_width`.
  - **ignored** — log at info level, naming the mount point and that no `config.toml` was present. Do nothing else. ("Ignored at info level and silently otherwise" in the previous draft was self-contradictory: log it, at info, and take no action. ### Layer: Packaging & Docs

- [x] Step 29: In `install.sh`, create `/media/mural` (root-owned `0755` — the kiosk user only needs traverse) and install the udev automount rule at `/etc/udev/rules.d/99-mural-usb.rules` matching `ACTION=="add"`, `SUBSYSTEM=="block"`, `SUBSYSTEMS=="usb"`, `ENV{ID_FS_USAGE}=="filesystem"` and running `systemd-mount --no-block --collect -o ro,nosuid,nodev,noexec,uid=<kiosk uid>,gid=<kiosk gid>,umask=0077 $devnode /media/mural/%k`, with the installing user's real uid/gid substituted; then `udevadm control --reload-rules && udevadm trigger`. Add the USB workflow — copy `config.toml` from `content/` onto the stick alongside the images — to the closing "next steps" output. Idempotent, like the existing Samba block.

  Four constraints on the rule itself:
  - **The `99-` prefix is required, not cosmetic.** `ENV{ID_FS_USAGE}` is set by the `blkid` builtin invoked from Debian's `60-persistent-storage.rules`; a rule sorting before that one sees the variable unset and never matches.
  - **Write it as two rules keyed on `ENV{ID_FS_TYPE}`, not one.** `uid=`, `gid=`, and `umask=` are FAT/exFAT/NTFS driver options, **not** generic VFS options: ext4, btrfs, and xfs reject unknown options and **fail the mount entirely**. With a single rule carrying `uid=` unconditionally, every ext4- or NTFS-formatted stick fails to mount, never appears in `/proc/self/mountinfo`, and produces no event, no log line, and no diagnosis — silence, not the "unreadable volume → ingest failure, logged" case the Analyst describes. So: one rule matching `ENV{ID_FS_TYPE}=="vfat|exfat|ntfs"` with `-o ro,nosuid,nodev,noexec,uid=<uid>,gid=<gid>,umask=0077`, and one matching the complement with `-o ro,nosuid,nodev,noexec` only. The generic four are true VFS options and are safe everywhere. An ext4 stick then mounts, and is merely unreadable if its files are root-owned — a real mount, a real permission error, a real log line.
  - **Guard against a USB-boot deployment mounting its own root filesystem: no working in-rule guard exists, and this is confirmed on real hardware, not just argued.** A Pi booted from a USB SSD has a root partition matching every condition in this rule, and udev would give the live root a second read-only mount under `/media/mural/`. Three candidate guards were considered and all three fail: `ENV{ID_FS_TYPE}!="swap"` is a no-op (swap has `ID_FS_USAGE=other`, so the existing `=="filesystem"` match already excludes it); "skip devices already in `/proc/self/mounts`" is not expressible in a udev rule without shelling out to a helper script; and `ATTRS{removable}=="1"`, this plan's original choice, **cannot ever match, on any hardware** — confirmed during Step 34 hardware validation on `pi3b.local`. udev requires `SUBSYSTEMS=="usb"` and an `ATTRS{}` match to be satisfied by the *same* ancestor device, but the numeric `removable` flag (`0`/`1`) exists only on the block-layer disk device (subsystem `block`), while the actual `usb`-subsystem ancestor has a *different* attribute also named `removable`, holding a string (`"fixed"`/`"removable"`/`"unknown"`) — and on the test stick's mass-storage bridge chip, it reported `"fixed"` regardless of being genuine removable flash media. No ancestor can satisfy both conditions at once, so a rule built this way silently never matches *any* USB stick — not a narrow USB-SSD edge case, but the entire feature, on ordinary consumer hardware. **The guard is dropped entirely.** `docs/INSTALL.md`'s only supported deployment boots from the SD card, so a USB-boot Pi's root filesystem getting a second read-only mount under `/media/mural/` is an accepted residual risk for an unsupported configuration, not something this rule needs to guard against.
  - Mural's `-media-dir` default (`/media/mural`, Step 28) and this rule's mount path are two independent literals that must agree. Note the coupling in a comment in both places.
